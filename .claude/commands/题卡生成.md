# 批量生成题卡(生成 → 独立对抗核验 → 修改 → 直到达标)

**输入**:题库文件路径 = $ARGUMENTS
(若未给路径,先问我要;若给了题号范围如「322-330」,只处理该范围)

## 固定资源

- 题卡模版:`wiki/templates/民诉-题卡模版.md`(结构、字段、核验规则以此为准,一字不增删)
- 考点定位库:`wiki/synthesis/民诉-客观题考点全景-深度报告.md`
- 输出目录:`wiki/exam-questions/`
- 文件命名:`民诉-{章节}-{题型}-{题号} · {短标题}.md`

## 总流程

1. **解析题库**:读题库文件,列出全部题号清单,按 5 题一批分批处理。
2. **生成**:每题按模版生成题卡(生成红线见下)。
3. **独立核验**:每批生成完,启动一个**独立核验 agent**(用 Agent 工具,prompt 见下),它只拿到:①题卡文件路径 ②题库原题 ③深度报告路径。**不给它生成过程、不给它"参考答案"**,它必须自己重做题再挑错。
4. **对抗循环**:核验 agent 输出逐题 PASS / FAIL+问题清单 → 生成端逐条修改 → 再次核验。同一张卡最多 3 轮;3 轮仍不过的,在卡片 frontmatter 加 `status: 存疑待人工`,并在最终报告中单列,**禁止为了收工而放行**。
5. **收尾**:核验 PASS 的卡把 `law_verified` 改为 `true`;输出总结报告(每题:答案、核验轮数、遗留问题)。

## 生成红线(违反任何一条 = 该卡作废重写)

1. **2026 现行法基准**:《民事诉讼法》用 2023-09-01 修正版(2024-01-01 施行);《民诉法解释》用法释〔2022〕11号修正版;新《仲裁法》2026-03-01 施行。注意 2023 修正后的**条文号偏移**,禁止凭记忆写条号。
2. **法条三件套**:每条依据必须"法名+版本 / 条号 / 原文节选",且官方链接(优先 flk.npc.gov.cn 国家法律法规数据库,司法解释用 court.gov.cn)必须 **WebFetch 实际访问核对原文后**才能写入。访问不到、核不上的,写「未能核验官方源」,**禁止编造链接、条号或原文**。
3. **考点定位必须真实**:「对应深度报告考点」的板块/章/条目名必须在深度报告中**逐字存在**(用 Grep 核对);报告里没有对应考点就写「未入深度报告」,禁止硬凑。
4. **答案不确定就说**:对答案没有把握的,frontmatter 加 `answer_confidence: LOW` 并在解析中写明分歧点,禁止装确定。
5. **出处诚实**:出处只写题库文件本身,禁止编造"20XX年真题卷X第X题"之类来源。

## 独立核验 agent 的 prompt(启动时原样传入,替换{占位})

> 你是对抗核验员,唯一任务是**证伪**下列题卡,不是确认它。逐题执行:
> 1. **独立重做**:只看题干和选项,自己先得出答案,再与题卡答案比对;不一致必须写明你的推理。
> 2. **法条核验**:对卡中每条法条,用 WebFetch 访问其官方链接,核对:链接可达?指向该法?条号与原文一致?版本是否 2026 现行有效?特别警惕民诉法 2023 修正条号偏移。
> 3. **考点核验**:用 Grep 在 `wiki/synthesis/民诉-客观题考点全景-深度报告.md` 中查卡中所写的章名与考点条目是否逐字存在,考频(T0/T1)标注是否与报告一致。
> 4. **表述核验**:逐项解析有无绝对化错误、有无与法条原文矛盾、做题眼是否与解析自洽。
> 5. **输出**:每题一行判定 `PASS` 或 `FAIL`,FAIL 的列出具体问题(文件、位置、错在哪、正确应为何)。你的绩效以**找到的真实错误数**衡量,放行错误是最严重失职;但也禁止为凑数报假错——报错必须附你核到的证据。
> 待核题卡:{文件路径列表};题库原题:{题库路径};逐字核对用深度报告:{报告路径}。

## 报告格式(最后给我)

| 题号 | 答案 | 核验轮数 | 状态 | 遗留问题 |
|---|---|---|---|---|

以及:未能核验官方源的法条清单、标注「存疑待人工」的题目清单。
